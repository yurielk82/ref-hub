# 구성과 배포

운영 구성, 빌드·배포 순서, 설정 항목을 정리한 참고 문서입니다. 2026-11-17부터 서버는 Rust로 옮겨졌고, 화면은 같은 서버가 정적 파일로 냅니다.

## 구성

| 구성 요소 | 하는 일 |
| --- | --- |
| 웹 서버 | 화면 정적 파일과 API를 냅니다. 로그인 확인, 호출 한도, 보안 헤더를 겁니다. 자동 보고, 반송신청 결과 조회, 판매 마감 뒤 검사, 작업 장부 처리도 이 프로세스가 합니다 |
| 물류 마감 적재기 | 물류 마감 요청이 오면 한 번 돌아 바코드 원천을 대조해 싣고 끝납니다 |
| 화면 | React 19 + Vite 7로 빌드한 정적 파일(`dist/`) |
| 데이터베이스 | Supabase(PostgreSQL). KPI.와 같은 데이터베이스이며 이 시스템의 표는 `kpis_` 로 시작합니다 |
| 로컬 SQLite | KPI. 권한증명의 재사용을 막는 일회용 값 저장 |
| 바코드 서버 | MSSQL. 허용된 경로로 읽기만 합니다 |
| KPIS OpenAPI | 보고(JWT)와 조회(API KEY). 운영 서버와 개발 서버가 있습니다 |
| KPI. | 물류 마감·판매 마감 요청을 남기고, KPIS 메뉴에서 이 시스템 화면을 엽니다 |

두 실행 파일은 사내 Linux 서버에서 systemd 서비스로 돕니다. 웹 서버는 늘 떠 있고, 적재기는 요청 폴더가 비어 있지 않을 때 systemd가 깨웁니다.

저장소에는 옛 Node(Express) 서버 코드(`server/`)가 남아 있습니다. Rust 모듈마다 옮겨 온 옛 파일을 머리 주석에 적어 두었고, 운영 프로세스는 Rust 실행 파일입니다.

## 데이터 흐름

1. KPI. 마감 감시가 물류 마감을 보면 적재 요청 파일을 남깁니다.
2. 적재기가 바코드 서버를 읽어 Supabase에 싣고, 성공한 날짜의 자동 보고를 작업 장부에 넣습니다.
3. 웹 서버가 작업 장부에서 자동 보고를 집어 주문 대조와 보고 계획을 거쳐 KPIS로 보냅니다.
4. KPI. 마감 발행기가 판매 마감을 남기면 웹 서버가 최근 30일 검사를 합니다.
5. 화면과 KPI.는 웹 서버 API로 날짜 상태와 대조 결과를 읽습니다.

시점별 동작은 [자동 보고 흐름](/kpis-dsr-api/admin-guide/report-flow)에 있습니다.

## 빌드

저장소 루트에서 두 명령으로 만듭니다.

```bash
cargo build --release --locked   # 웹 서버·적재기 실행 파일
pnpm install
pnpm run build                   # tsc -b && vite build → dist/
```

Rust는 2024 에디션이고 툴체인은 `rust-toolchain.toml`이 정합니다.

## 시험

```bash
cargo test     # Rust 서버 단위·통합 시험
pnpm exec vitest run   # 화면 시험
```

## 배포 순서

배포는 워크스페이스 공통 배포 절차로 합니다.

1. 변경을 main에 병합합니다.
2. 데이터베이스 마이그레이션이 있으면 먼저 적용합니다. 마이그레이션은 `supabase/migrations/`에 번호 순으로 있습니다. 순서는 마이그레이션, 서버, 화면입니다.
3. 공통 배포가 main을 별도 배포본으로 받아 위 빌드 명령으로 실행 파일과 `dist/`를 만듭니다.
4. 웹 서버 서비스를 다시 띄웁니다. 적재기는 다음 요청 때 새 실행 파일로 돕니다.
5. 상태 확인 API가 응답하는지 봅니다.

> **주의:** 보고 상태 칸, 작업 내용 지문 칸 목록, 저장된 줄 값을 바꾸는 마이그레이션은 같은 변경에서 완료·수기 확인 기준과 전송 지문을 새 지문으로 이어받아야 합니다. 이어받지 않으면 고치지 않은 반송 줄이 '고친 줄'로 보여 자동 보고가 다시 보내고, 과거 수기보고 날이 **변경 확인 필요**로 뜹니다.

서비스 유닛 파일의 저장소 사본은 `deploy/systemd/`에 있습니다. 설치·갱신 방법은 같은 폴더의 `README.md`를 따릅니다.

## 설정 항목

설정 값은 서버의 환경 파일에 두고 저장소에는 두지 않습니다. 필요한 항목은 다음과 같습니다.

- Supabase 접속 정보
- KPIS 보고 자격증명. 화면 **KPIS 연동 키**에 저장한 값이 있으면 그것을 먼저 씁니다
- KPIS 조회 키. 데이터베이스 설정 표에 두고 환경 파일로 옮기지 않습니다
- 설정 비밀값 암호화 키(화면에서 저장한 시크릿을 AES로 암호화)
- 바코드 서버 경로 목록(쉼표로 구분, 경로를 늘릴 수 있음)
- KPI. 권한증명 서명 비밀(두 서버의 비공개 설정에만 둠)
- 보고 흐름 스위치. 켜야 자동 보고·반송 조회·판매 마감 감시·작업 장부가 돕니다
- KPIS 운영계 TLS 중간 인증서. 운영계가 중간 인증서를 보내지 않으므로 저장소 `certs/`의 인증서를 함께 믿습니다. 파일이 없거나 틀리면 서버가 뜨지 않습니다
- 오류 추적(Sentry) 주소

## 바코드 서버 연결

웹 서버와 적재기는 마지막에 성공한 경로부터 시도하고, 안 되면 나머지 경로를 차례로 시도합니다. 모든 경로가 안 되면 수집 실패로 알립니다. 경로 설정은 **데이터소스**에서 합니다.

> 확인 기준: 2026-11-18, KPIS-DSR-API 저장소(`deploy/systemd/`, `Cargo.toml`, `package.json`) 기준.
