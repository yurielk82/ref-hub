# KPI 소개

KPI는 사내 영업 데이터를 한곳에서 조회·대조·보고하는 웹 시스템입니다. ERP 원천 자료와 공공 데이터를 매일 받아 매출·수금·채권·할인율·재고·반품·시장 숫자를 화면으로 보이고, 매달 손으로 만들던 월 보고서를 원본 양식 그대로 내려받게 합니다. 영업지원팀·회계팀·영업본부·경영진이 같은 원천 숫자를 부서별 화면으로 봅니다.

**현재 상태:** 운영 중입니다. 2026년 3월에 개발을 시작해 사내 서비스(kpi.dvsharp.com, 로그인 필요)로 쓰고 있으며 기능을 계속 고칩니다. 근거는 저장소 README의 운영 배포 표, 2026-11-18의 운영 서비스 실행 상태, 같은 날까지 이어진 커밋 기록입니다.

![KPI 종합 현황 화면](/assets/selected-portfolio/images/pharmkpi/overview-content-d6a098019822.webp)

종합 현황에서 기준월의 매출·수금·채권 잔고·할인율·재고·반품 대표 지표와 전사 매출 월별 추세를 한 화면에서 봅니다. 캡처의 이름·금액은 공개용 예시 값입니다.

부서마다 주로 여는 메뉴가 다릅니다.

| 사용자 | 주로 하는 일 | 주로 여는 1차 메뉴 |

| 영업지원팀 | 마감 확인, 주문·수금·채권·재고 조회, 기준 정보 관리 | **영업지원팀**, **영업리포트** |
| 회계팀 | 거래처 원장, 월말 채권 차이와 수금조정 확인 | **회계팀** |
| 영업본부 | 월간 KPI, 영업 활동 분석과 회의 자료 | **영업본부**, **SFE** |
| 경영진 | 기준월 실적과 증감 원인 확인 | **KPI** |
| 관리자 | 자료 갱신 확인, 사용자·메뉴·입력값 관리 | **원본 자료**, **관리자 설정** |

## 1차 메뉴

왼쪽 레일에 1차 메뉴 11개가 있습니다. 레일은 누구나 쓰는 **공통** 묶음, 사람마다 따로 켜는 **특화** 묶음, 관리자용 **바닥 고정** 묶음으로 나뉩니다. 사용자에게는 관리자가 열어 준 메뉴만 보입니다.

| 묶음 | 1차 메뉴 | 하는 일 |
| --- | --- | --- |
| 공통 | **KPI** | 종합 현황, 월간 KPI, 매출·수금·채권·할인율·재고·반품별 개요·구성·기간 비교·증감 원인, KPI 자유분석, 데이터 대조 |
| 공통 | **영업리포트** | 피벗 분석, 월 보고서 4종, 거래처 방문준비, 분기별 매출실적, 매출 조회 |
| 공통 | **영업본부** | 월간 KPI(KPI 메뉴의 같은 화면을 함께 보입니다) |
| 공통 | **영업지원팀** | 주문 내역, 수금 내역, 재고 현황, 마감 현황, 채권 조회, 거래처 원장, 수금조정 내역, 사업자 휴·폐업 조회, 품목·거래처·사원·병원·약국·CSO 업체 마스터 |
| 공통 | **회계팀** | 회계팀 현황, 거래처 원장, 수금조정 내역, 사업자 휴·폐업 조회, 수금 예상 |
| 공통 | **시장** | 시장 포트폴리오, 처방 동향, 대조약·경쟁제품, 주력품목 시장, 전국 시장, 생산실적, 원료의약품(DMF) 조회, 판매 지도 |
| 특화 | **SFE** | 영업 일보와 도매 매출로 보는 활동·도달·성과 분석, SFE 발표 자료 |
| 특화 | **S&OP** | 수요·공급·재고 검토를 월간 계획 흐름으로 묶은 시제품 |
| 특화 | **KPIS** | 의약품 공급내역보고의 보고 상태·보고 작업·주문 대조 |
| 바닥 고정 | **원본 자료** | 데이터 갱신 현황, ERP 원본 자료 13종, 공공 API 수집 현황과 원본 |
| 바닥 고정 | **관리자 설정** | 운영 현황, 입력·규칙, SFE 관리, 유비스트 업로드, 사용자·메뉴·휴일·공공데이터 API·AI 설정 |

레일 아래에는 메뉴 권한과 상관없이 누구나 여는 **용어사전**이 있습니다.

## 관련 기능

아래 기능은 KPI와 같은 자료를 쓰지만 상태와 범위가 다릅니다. 자세한 내용은 각 사례에서 봅니다.

| 기능 | 상태 | 내용 | 더 보기 |
| --- | --- | --- | --- |
| SFE 영업활동 분석 | 사용 중 | 영업 일보와 매출을 매일 함께 분석하고 월 발표 자료를 만듭니다. | [SFE 사례](/ax/projects/kpi-sfe) |
| S&OP 수요·공급 계획 | 실무 미적용 시제품 | 별도 앱으로 만들어 KPI 안에 넣은 개인 시제품입니다. 실제 업무에는 쓰지 않습니다. | [S&OP 사례](/ax/projects/kpi-snop) |
| 의약품 공급내역보고 | 사용 중 | 보고 실행은 별도 시스템이 맡고, KPI의 **KPIS** 메뉴는 그 시스템의 결과를 읽어 보입니다. | [공급내역보고 매뉴얼](/kpis-dsr-api) |
| 경영진 데일리 리포트 | 사용 중 | 일일 실적과 판매 구성을 보여 줍니다. 매일 새벽 판매·수금 집계를 원천 자료와 대조하고, 차이가 난 월은 다시 검산한 뒤 반영합니다. | [경영진 리포트 사례](/ax/projects/bi) |
| 유통재고 분석 | 준비 중 | 외부 유통재고 자료가 아직 들어오지 않습니다. 창고재고 조회 화면을 먼저 만들었습니다. | [유통재고 사례](/ax/projects/kpi-inventory) |

## 숫자를 읽는 기준

KPI는 숫자를 보이기 전에 그 숫자의 정의를 먼저 맞춥니다. 다른 보고서와 값이 다를 때는 아래 기준부터 확인합니다.

- **매출**은 도매 판매에서 반품과 매출할인을 빼고 수출과 수탁생산(CMO)을 더한 값입니다.
- **CSO**(영업대행)는 도매 안에서 수수료 지급 대상 품목을 가르는 분류입니다. 별도 매출 채널로 더하지 않습니다.
- 표의 컬럼 이름 앞 `(BI)`·`(규칙)`·`(구ERP)`는 값의 출처입니다. `(BI)`는 원천 그대로, `(규칙)`은 규칙 표로 만든 값, `(구ERP)`는 옛 ERP 폐기(2026-08) 전까지 옛 ERP에서 옮겨 둔 읽기 전용 값입니다.
- 원천 자료는 끝까지 다 받은 묶음만 화면에 씁니다. 받는 도중의 자료는 보이지 않습니다.
- 빈칸과 0은 다릅니다. 자료가 없으면 **자료 없음**으로 표시합니다.

## 구성 요약

| 구분 | 사용 기술 |
| --- | --- |
| 화면 | Next.js 16, React 19, TypeScript, Astryx 디자인 시스템, Recharts |
| 데이터 | PostgreSQL(Supabase 셀프호스팅), Prisma 7 |
| 로그인 | Supabase Auth, 1차 메뉴별 권한 |
| 외부 자료 | 모회사 BI 인터페이스, 심평원·식약처·국세청 공공 API |

| 운영 | 사내 서버, 정해진 시각의 자동 작업, Sentry 오류 관측 |
| 검사 | Vitest, Playwright, CircleCI |
