# 데이터 반영과 자동 작업

KPI 화면의 숫자가 어디서 오고, 언제 어떤 순서로 반영되며, 반영이 늦을 때 어디서 확인하는지 정리합니다.

## 자료 원천

KPI는 원천 자료를 받아 화면에 보일 뿐 원천을 고치지 않습니다. 사람이 채우는 표는 원천으로 쓰지 않으며, 아래 표의 직접 입력 항목만 예외입니다.

| 원천 | 들어오는 자료 | 방식 |
| --- | --- | --- |
| 모회사 BI 인터페이스 | ERP의 판매·수금·채권·LOT 재고·마감·거래처·품목·사원 등 원천 화면 13종 | 자동 |
| 옛 ERP 적재분 | 옛 ERP 폐기(2026-08) 전까지의 채권·재고 월말 이력과 일부 마스터 칸 | 읽기 전용, 새로 받지 않음 |
| 공공 데이터 | 심평원 약가·의약품 사용 정보, 식약처 허가·생산실적·원료의약품, 국세청 휴·폐업 상태, 도로명주소 | 자동 |
| 병원·약국 명단 | 병원·약국 마스터 | 별도 수집 서비스에서 받음 |
| 영업 일보 | SFE 분석에 쓰는 방문 기록 | 자동, 하루 두 번 |
| 직접 입력 | 외부 입력, 유비스트 원외처방, 소송처, 휴일, CSO 업체, 종합도매 목록 | 관리자가 화면에서 |

직접 입력하는 방법은 [외부 입력과 유비스트 자료 올리기](/pharmkpi/user-guide/data-upload)에 있습니다.

## 받는 방식

원천 자료는 한 번에 끝까지 받은 묶음(세대)만 화면에 씁니다.

1. 원천 화면을 새 세대로 받아 저장합니다.
2. 다 받은 세대만 게시합니다. 받는 도중에 실패하면 이전 세대가 그대로 보입니다.
3. 게시가 끝나면 그 자료를 쓰는 KPI 지표와 화면 캐시를 다시 계산합니다.
4. 모든 실행은 실행 기록으로 남습니다.

데이터베이스를 많이 쓰는 작업은 한 줄로 서서 차례로 돕니다. 두 작업이 같은 표를 동시에 쓰지 않게 하기 위해서입니다.

자료마다 지키는 규칙이 있습니다.

- 판매는 원천 세대와 그것으로 만든 주문 내역 두 층뿐입니다. 지난 달 판매가 정정되면 게시 세대에 바로 반영하고, 영향 받은 달의 KPI를 다시 계산합니다.
- 채권은 원천이 달별 이력을 주므로 확정된 달도 원천에 맞춥니다.
- 재고는 확정된 달의 값과 캐시를 덮지 않습니다.

## 하루 일정

자동 작업은 아래 시각에 시작합니다. 시각은 한국 시간입니다.

| 시각 | 작업 |
| --- | --- |
| 평일 8시~24시, 10분마다 | 원천 마감표를 확인합니다. 판매·수금이 마감되면 그 자료를 다시 받아 게시하고 마감 확정 알림을 보냅니다. 채권·재고는 마감 뒤 같은 값이 10분 간격으로 세 번 확인되면 받습니다. |
| 평일 18시대·23시대 | 판매·수금 마감이 실제로 반영됐는지 한 번 더 확인합니다. |
| 매일 0시 직후 | 날짜가 넘어간 자료의 발행을 요청합니다. |
| 매일 4시 | 새벽 작업을 시작합니다. 아래 순서로 이어 돕니다. |
| 매일 6시 40분, 18시 40분 | 영업 일보를 받습니다. |
| 매일 7시 | 공공 데이터 가운데 차례가 된 것을 받습니다. 실패하면 5시간 뒤 한 번 더 시도합니다. |
| 매일 7시 20분 | 전국 의약품 사용량 요약을 받습니다. |
| 매일 8시 30분 | 데이터 갱신 상태 하루 요약을 냅니다. |
| 매일 9시 10분 | 심평원 약제급여목록표 새 판이 나왔는지 확인합니다. |

새벽 작업은 시작만 시각으로 정하고 나머지는 앞 단계가 끝나면 이어집니다.

1. 매달 11일부터 27일까지는 원천 전체를 다시 받습니다.
2. 야간 검증을 돕니다. 지난 달 채권·재고 원장을 월별 보존본과 거래처별로 대조하고, 맞지 않는 달은 다시 받습니다.
3. KPI 발행본, 거래처 마스터, 담당자 배정을 다시 만듭니다.
4. 검증이 성공하면 SFE 스냅샷을 만듭니다.
5. 새벽 작업이 끝나면 성공·실패와 상관없이 거래처 사업자번호 전체의 휴·폐업 상태와 주소 표준화를 갱신합니다.

## 반영 상태 확인하기

반영이 늦은지 판단할 때는 대상 표가 실제로 갱신됐는지와 그 작업의 실행 기록을 봅니다. 수집 작업이 성공했다는 표시만으로 판단하지 않습니다.

1. **원본 자료** 메뉴의 **갱신 현황** 묶음에서 **데이터 갱신 현황**을 엽니다.
2. **갱신 상태 요약**에서 문제가 있는 자료 수를 봅니다.
3. 표에서 자료마다 **제공처**, **기준기간**, **최근 실행**, **허용 지연**, **정상 경과**, **행수**를 확인합니다. 정상 경과가 허용 지연을 넘긴 자료가 늦은 자료입니다.
4. 시각표를 보려면 **자동 갱신 일정**을 엽니다.

공공 데이터는 **원본 자료** 메뉴의 **공공 API 수집 현황**에서 API마다 마지막 수집을 봅니다.

**월간 KPI** 숫자를 지금 다시 계산해야 하면 관리자가 **월간 KPI** 화면의 **BI에서 갱신**을 누릅니다. 이 단추는 관리자에게만 보입니다.

## 알림

반영이 늦거나 실패하면 관리자에게 알립니다.

- 자동 작업이 재시도까지 실패하면 **데이터 갱신 지연 (관리자)** 푸시 알림이 갑니다.
- 야간 검증이 운영 숫자 대조에 실패하면 실패 사유를 기록으로 남기고 알림 하나로 올립니다.
- 운영 알림은 사건 단위로 쌓이며, 복구 신호가 없는 사건형 알림은 7일 동안 다시 나지 않으면 닫힙니다.

## 관련 쪽

- 숫자가 맞지 않을 때는 [문제 해결](/pharmkpi/admin-guide/troubleshooting)을 봅니다.
- 데이터 흐름 전체 그림은 **관리자 설정** 메뉴의 **데이터 구조도**에 있습니다.
