# 구성과 배포

이 쪽은 EV Motor Reliability를 이루는 부분과 각 부분을 배포하는 순서를 정리합니다.

## 구성

운영 화면은 한 서버에서 웹과 API를 함께 냅니다.

| 부분 | 기술 | 운영 위치 |
|------|------|-----------|
| 웹 화면 | Next.js 16 standalone 빌드 | 운영 서버 |
| API | FastAPI, uvicorn | 운영 서버 |
| 사용자 인증 | Neon Auth(Google 로그인) | 외부 서비스 |
| 저장소(DB) | Neon PostgreSQL | 외부 서비스 |
| AVL 변환기 PC 프로그램 | PyInstaller 단일 실행 파일 | 사용자 PC |
| 펌웨어 | C, TMS320F2838x | 시험 장비 |

요청은 다음 순서로 흐릅니다.

1. 브라우저가 `avl.dvsharp.com`에 접속합니다.
2. 리버스 프록시가 `/api/v1/` 아래 요청은 API로, 나머지는 웹 화면으로 보냅니다.
3. 웹 화면은 브라우저의 API 호출을 `/agent-api` 경로로 받아 API의 `/api/v1`로 다시 보냅니다.
4. 대시보드의 최근 시뮬레이션·지표 숫자는 웹 화면 서버가 Neon PostgreSQL을 직접 읽습니다.

## 서버 배포

운영 서버 배포는 작업 공간 공통 배포 도구가 맡습니다. 도구는 저장소 `master` 브랜치를 받아 다음을 합니다.

1. API는 배포용 체크아웃에 Python 가상환경을 만들고 `api.main:app`을 uvicorn으로 다시 띄웁니다.
2. 웹 화면은 `web/`에서 `pnpm run build`로 standalone 빌드를 만들고, 정적 파일과 `public/`을 함께 복사한 뒤 새 빌드로 바꿉니다.
3. 웹은 로그인 화면, API는 API 문서 화면(`/docs`)이 응답하는지 확인합니다.

배포 뒤 다음을 확인합니다.

- `avl.dvsharp.com/api/v1/health` 응답의 `services`에서 `python`, `database`, `git`이 `connected`인지 봅니다. 운영 서버에는 시험 장비가 없으므로 `hardware`는 `disconnected`가 정상입니다.
- `avl.dvsharp.com/avl-converter`를 열어 "세션 생성 실패" 없이 첫 단계가 나오는지 봅니다.

> **주의:** AVL 변환기의 내장 기준 XML과 시험 CSV는 git에 올리지 않는 파일입니다. API는 배포용 체크아웃의 `ref/AVL_XML_Profile_Converter_V1_0_및 데이터/` 폴더에서 정해진 이름의 기준 XML(`avl_converter_router.py`의 `DEFAULT_TEMPLATE_XML`)을 찾습니다. 이 파일을 서버에 따로 두어야 웹에서 내장 템플릿을 씁니다. 없으면 사용자가 **고급: 다른 base XML 사용 (선택 사항)** 항목에서 직접 올려야 합니다.

## 설정 값

설정은 환경 변수로 넣습니다. 값은 서버의 비밀 파일에만 두고 저장소에 올리지 않습니다. 항목 이름은 저장소의 `.env.example`과 `web/.env.example`에 있습니다.

| 부분 | 주요 항목 |
|------|-----------|
| API | `EVMOTOR_DATABASE_URL`, `EVMOTOR_CORS_ORIGINS`, `EVMOTOR_AUTH_ENABLED`, `EVMOTOR_RATE_LIMIT_*`, `EVMOTOR_CHAT_ENABLED`, `EVMOTOR_HARDWARE_SERIAL_PORT` |
| 웹 화면 | `DATABASE_URL`, `NEON_AUTH_BASE_URL`, `NEON_AUTH_COOKIE_SECRET`, `NEXT_PUBLIC_AGENT_URL`, `AGENT_BACKEND_URL` |

## AVL 변환기 실행 파일

변환기 폴더(`ref/AVL_XML_Profile_Converter_V1_0_및 데이터/AVL_XML_Profile_Converter_V1_0/`)를 바꾸는 PR마다 CircleCI가 Windows 환경에서 `AVL_XML_Profile_Converter.exe`를 만들고 `--help`로 실행을 확인한 뒤 빌드 산출물로 남깁니다. GitHub Releases에는 올리지 않습니다.

사용자에게 줄 실행 파일은 다음 둘 중 하나로 얻습니다.

- 해당 PR의 CircleCI 작업 산출물에서 내려받습니다.
- Windows PC에서 변환기 폴더의 `build_exe.bat`를 실행합니다. `dist\AVL_XML_Profile_Converter.exe`가 생깁니다. PyInstaller는 다른 운영체제용 파일을 만들지 못하므로 Windows에서만 빌드합니다.

## 장비가 있는 PC에서 띄우기

하드웨어 수집과 긴급 정지는 시험 장비가 UART로 연결된 PC에서 API를 띄워야 동작합니다.

1. 저장소를 받고 Python 3.10 이상 가상환경을 만듭니다.
2. `pip install -e ".[web]"`로 설치합니다.
3. `automation/config.yaml.example`을 `automation/config.yaml`로 복사하고 시리얼 포트를 적습니다.
4. `python agent.py`를 실행합니다. 포트를 바꾸려면 `--port`, 브라우저를 열지 않으려면 `--no-browser`를 붙입니다.

## 개발 환경

개발할 때는 API와 웹을 따로 띄웁니다.

```bash
pip install -e ".[dev,web]"
python agent.py --no-browser
cd web
pnpm install
pnpm run dev
```

컨테이너로 한 번에 띄우려면 저장소 최상위 폴더에서 `docker compose up`을 실행합니다. API(`app`)와 웹(`web`) 두 서비스가 뜹니다.

## 변경 이력

웹 화면은 처음에 Vercel에 배포했습니다. 저장소에는 `master` 브랜치만 Vercel에 배포하는 `vercel.json` 설정이 남아 있습니다. 운영 화면은 지금 API와 같은 서버에서 냅니다.
