# 데이터베이스

> **참고:** CSO 정산 포털의 정산 업무는 2026-09-29에 다른 정산 시스템으로 옮겼습니다. 이 쪽은 운영 당시 구성의 기록입니다.

이 쪽은 포털 자료가 어디에 어떤 모양으로 저장되는지, 정산 자료가 어떻게 들어가고 바뀌는지 정리합니다.

## 저장 위치

포털은 워크스페이스 공용 Supabase(셀프호스팅, PostgreSQL 17.6)를 씁니다. 다른 제품과 같은 데이터베이스를 쓰므로 포털의 표는 모두 `csoweb_` 접두사로 구분합니다. 표 이름 목록은 `src/constants/tables.ts` 한 곳에 있습니다.

- 서버 API는 서비스 역할 키로 데이터베이스에 접근합니다. 화면(브라우저)이 데이터베이스에 바로 붙지 않습니다.
- 회원사가 볼 수 있는 범위는 서버 코드가 요청마다 정합니다. 방법은 아래 "회원사 자료 범위"에 있습니다.
- Supabase Auth는 쓰지 않습니다. 로그인은 [인증과 권한](/csoweb/admin-guide/authentication)에 있습니다.

## 주요 표

| 표 | 담는 것 |
|------|------|
| `csoweb_users` | 회원 계정. 사업자번호가 로그인 아이디이고, 승인 여부, 등급, 로그인 실패 횟수, 정산 계좌를 담습니다. |
| `csoweb_settlements` | 정산 자료. 엑셀 한 줄이 한 줄입니다. 열 이름은 SIT 엑셀의 한글 열 이름(`정산월`, `처방월`, `CSO관리업체`, `거래처명`, `제품명`, `수량`, `금액`, `제약수수료_합계` 등)을 그대로 씁니다. |
| `csoweb_cso_matching` | CSO 매칭. 정산서 업체 표기(`cso_company_name`, 기본 키)와 회원 사업자번호를 잇습니다. |
| `csoweb_settlement_uploads` | 정산월별 업로드 기록과, 그 달을 열어 본 업체 목록 |
| `csoweb_column_settings` | 회원사 화면에 보일 열, 순서, 필수 여부, 합계 여부 |
| `csoweb_company_settings` | 사이트 설정 한 줄. 회사 정보, 이메일 발송 설정, 알림 켜고 끄기, 정산서 Notice 문구, 조회 기준 연월 |
| `csoweb_member_profile_change_requests` | 회원사의 정보 변경 요청과 처리 결과 |
| `csoweb_email_logs` | 보낸 메일 기록과 상태 |
| `csoweb_mailmerge_batches` | 메일머지 발송 묶음 |
| `csoweb_export_logs` | 회원사의 엑셀 다운로드 기록. 하루 다섯 번 제한에 씁니다. |
| `csoweb_password_reset_tokens` | 비밀번호 찾기 인증코드와 변경 링크. 30분, 한 번만 쓸 수 있습니다. |
| `csoweb_announcements` 외 | 공지와 첨부 파일 |
| `csoweb_edi_verification_*` 외 | EDI 검토 자료. [EDI 검증 매뉴얼](/edi-verification)이 다룹니다. |

## 회원사 자료 범위

회원사가 정산서를 열면 서버가 다음 순서로 자료를 고릅니다.

1. 로그인 세션에서 사업자번호를 꺼냅니다.
2. `csoweb_cso_matching`에서 그 사업자번호에 이어진 업체 표기를 모두 찾습니다.
3. `csoweb_settlements`에서 `CSO관리업체`가 그 표기 가운데 하나인 줄만 고릅니다.
4. 사이트 설정의 조회 기준 연월보다 앞선 달을 뺍니다.
5. 정산 제외로 지정된 거래처는 줄을 남기되 금액·수수료를 0으로 바꾸고 거래처명 뒤에 " (정산 제외)"를 붙입니다.

관리자는 2~4단계를 거치지 않고 모든 자료를 봅니다.

## 정산 자료가 들어가고 바뀌는 방식

정산 자료는 관리자 화면의 엑셀 업로드로만 들어갑니다. 절차는 [정산서 올리기](/csoweb/user-guide/upload)에 있습니다.

- 엑셀 첫 시트만 읽습니다. 열 이름이 같거나 비슷한 데이터베이스 열에 짝지어 넣습니다.
- 500줄씩 나누어 넣습니다.
- 같은 정산월 자료가 이미 있으면 새 줄을 모두 넣은 뒤 그 달의 옛 줄을 지웁니다. 그래서 그 달 자료는 언제나 마지막으로 올린 파일과 같습니다.
- 넣은 뒤 서버가 정산월·업체 목록 캐시를 새로 만들고, EDI 검토 묶음을 새 자료에 맞춥니다.

2026-11-18 기준으로 정산 자료가 들어 있는 정산월은 2022-04부터 2026-06까지입니다. 2026-06 자료는 2026-06-30에 올라갔고, 그 뒤로 정산 줄이 든 업로드는 없습니다.

## 백업과 복원

- 공용 Supabase 데이터베이스 전체를 서버 공통 백업이 매일 PostgreSQL 덤프로 떠서 암호화해 외부 저장소에 보관합니다. 포털 표도 여기에 들어갑니다.
- 한 달 치 정산 자료는 원본 엑셀을 다시 올리면 그대로 복원됩니다. 같은 정산월 업로드가 그 달 자료를 통째로 바꾸기 때문입니다. 원본 엑셀은 따로 보관합니다.

> 확인 기준: 2026-11-18, csoweb 저장소와 운영 데이터베이스 읽기 조회 기준.
