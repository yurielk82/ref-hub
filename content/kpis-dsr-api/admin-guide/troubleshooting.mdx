# 문제 해결

증상별로 원인과 조치를 정리했습니다. 먼저 **KPIS 보고** › **로그**에서 **확인·오류만**을 켜고 최근 기록을 읽습니다. 자동 보고, 물류 마감 적재, 판매 마감 뒤 검사, 폴더 감시의 오류는 모두 여기에 남습니다. 메일 알림은 없습니다.

## 공급 자료 수집

| 증상 | 원인 | 조치 |
| --- | --- | --- |
| 날짜 카드가 **자료 확인 필요** · **최근 수집 실패** | 바코드 서버에 닿지 못했습니다. 사내망 수집 경로가 모두 끊긴 경우가 대부분입니다 | 수집 경로를 살립니다. 그 뒤 날짜 카드 `⋯` › **데이터 받아오기** |
| 로그에 "물류 마감 적재가 3번 실패해 멈췄습니다" | 같은 원인으로 적재기가 5분 간격 세 번 모두 실패했습니다 | 수집 경로를 살리면 다음 물류 마감 때 남은 요청을 함께 처리합니다. 기다릴 수 없으면 **데이터 받아오기** |
| **데이터 가져오기**의 **테스트**가 **실패** | 수집 경로 설정이 틀렸거나 경로가 끊겼습니다 | **데이터소스**에서 활성 경로를 확인합니다 |
| 로그에 형식이 틀린 마감 요청 기록 | KPI.가 달력에 없는 날짜 등으로 요청을 남겼습니다 | 적재기는 그 요청만 따로 옮겨 두고 나머지를 처리합니다. 운영자가 확인한 뒤 지웁니다 |
| 날짜가 **변경 확인 필요** · **변경 내용 대조** | 원천이 바뀌었는데 사람이 고쳤거나 보고한 날이라 덮지 않았습니다. 원천이 0줄인데 적재본이 있는 경우도 같습니다 | `⋯` › **변경 내용 확인**에서 다시 싣거나 줄마다 처리합니다([공급 자료 가져오기](/kpis-dsr-api/user-guide/daily-reports)) |
| 엑셀 올리기에서 "이미 저장된 날짜" | 그 날짜 자료가 이미 있습니다 | 보고 흔적이 없으면 **데이터 관리**에서 지운 뒤 다시 올립니다 |

## 보고

| 증상 | 원인 | 조치 |
| --- | --- | --- |
| 자동 보고가 아무것도 보내지 않음 | **자동 보고**가 꺼져 있거나 **API 보고 시작일**이 비어 있습니다 | **KPIS 연동 키**에서 확인합니다 |
| 자동 보고가 특정 날만 보내지 않음 | 결과 미확인 줄, 기한 지난 새 줄(늦은 보고), 정정할 수 없는 원천 변경, 같은 자료로 이미 시도함 가운데 하나입니다 | 로그의 보류 사유를 보고 해당 절차로 처리합니다. 사람이 고치면 다음 보고 때 다시 봅니다 |
| **결과 확인 필요**가 풀리지 않음 | 보고 저장 응답이 없었거나 결과 조회 실패가 이어졌습니다 | **API 결과 다시 확인** 뒤에도 남으면 업무포털에서 확인해 접수·미접수로 정리합니다([KPIS에 보고하기](/kpis-dsr-api/user-guide/pdf-export)) |
| **연결 테스트**가 **연결 실패** | 클라이언트 아이디·시크릿이 틀렸거나 서버(운영·개발)를 잘못 골랐습니다 | 키를 받은 서버와 같은지 확인하고 다시 넣습니다 |
| "요청 사업자번호와 JWT토큰 인증정보가 상이합니다" | **보고 사업자번호**가 키를 받은 업체와 다릅니다 | 사업자번호를 고칩니다 |
| 묶음 전체가 반송 | KPIS는 한 줄만 틀려도 묶음 전체를 받지 않습니다 | 보고 실행기가 틀린 줄만 빼고 다시 보냅니다. **이력**에서 단계 기록을 봅니다 |
| 같은 줄이 계속 반송 | 고치지 않은 내용으로 다시 보냈거나 사유를 잘못 짚었습니다 | 반송 코드의 해결 방법대로 칸을 고칩니다([반송 줄 고쳐 다시 보고하기](/kpis-dsr-api/user-guide/return-management)) |
| 정정·취소가 JD로 반송 | 정정·취소 기한(공급월 다음 달 말일)이 지났습니다 | 반송신청 뒤 업무포털 **반송보고**로 고칩니다 |
| HTTP 410으로 거절 | 요청 본문이 KPIS 한도를 넘었습니다(을지 약 3만 개 이상) | 일련번호가 1만 개 넘는 줄은 적재 때 나뉩니다. 나뉘지 않은 줄이면 그날을 다시 싣습니다 |
| 개발 서버에서 "거래처 미등록(CN)" | 개발 서버의 시험 계정에 우리 거래처가 없습니다 | 개발 서버에서는 정상입니다. 운영 거래처 등록 여부는 MA102로 봅니다 |
| 적기보고율이 목표 아래로 떨어짐 | 기한 지난 줄을 새 줄로 보내 늦은 보고가 생겼습니다 | 기한 지난 줄은 반송신청과 **반송보고**로만 고칩니다 |

## 대조

| 증상 | 원인 | 조치 |
| --- | --- | --- |
| **주문·KPIS 대조**에 **KPIS에 없음** | 그날 미보고·반송·결과 미확인 줄이 있습니다 | **KPIS 보고**에서 그날을 열어 보냅니다 |
| **주문에 없음** | 보고 뒤 주문이 취소·변경됐습니다 | 정정 기한 안의 API 접수 줄이면 판매 마감 뒤 검사가 정정·취소합니다. 거래처를 확실히 맞출 수 없으면 사람이 봅니다 |
| 대시보드 대조에 **확인 중** | 마지막 보고가 마지막 KPIS 집계 받기보다 늦습니다 | 보고 1분 뒤 집계를 다시 받으면 풀립니다 |
| 로그에 "판매 마감 뒤 대조가 36시간 넘게 완료되지 않았습니다" | 판매 마감 요청이 오지 않았거나 검사가 계속 실패했습니다 | 로그의 실패 사유를 봅니다. 예비 실행이 하루 한 번 돕니다 |

## 화면

| 증상 | 원인 | 조치 |
| --- | --- | --- |
| 칸을 고칠 수 없음 | 접수·포털 제출·결과 미확인 줄은 잠겨 있습니다 | 정정·취소나 반송신청을 씁니다 |
| 저장 오류 뒤 값이 되돌아감 | 다른 곳에서 먼저 바뀌었거나 그사이 보고된 줄입니다 | 날짜를 다시 열고 고칩니다 |
| 규칙이 다른 PC에서 안 보임 | 규칙과 수정 이력은 브라우저에만 저장됩니다 | 그 브라우저에서 다시 만듭니다 |
| 로그인 뒤 대기 화면에서 멈춤 | 관리자 승인 전입니다 | 관리자가 **사용자관리**에서 승인합니다 |

## 서버

| 증상 | 원인 | 조치 |
| --- | --- | --- |
| 화면이 열리지 않거나 API가 모두 실패 | 웹 서버가 멈췄습니다 | 서버의 서비스 상태와 시스템 로그를 보고 서비스를 다시 띄웁니다. 상태 확인 API 응답으로 확인합니다 |
| 웹 서버가 시작 직후 꺼짐 | KPIS 운영계 TLS 중간 인증서 파일이 없거나 틀렸습니다 | 배포본의 `certs/` 인증서를 확인합니다 |
| 자동 보고·반송 결과 조회·판매 마감 검사가 전혀 돌지 않음 | 서버 설정의 보고 흐름 스위치가 꺼져 있습니다 | 설정을 켜고 서버를 다시 띄웁니다 |
| 로그에 "보고 요청 폴더 감시 실패" | 요청 폴더 감시가 멈췄습니다. 물류 마감 뒤 자동 보고가 돌지 않고 밤 11시 보고만 돕니다 | 서버를 다시 띄우면 다시 감시합니다 |
| 배포 뒤 과거 수기보고 날이 한꺼번에 **변경 확인 필요** | 내용 지문을 바꾸는 마이그레이션이 완료 기준을 이어받지 않았습니다 | 같은 변경에서 완료·수기 확인 기준과 전송 지문을 새 지문으로 이어받는 마이그레이션을 더합니다([구성과 배포](/kpis-dsr-api/admin-guide/deployment)) |

## 진단 순서

1. **KPIS 보고** › **로그**에서 **확인·오류만**으로 최근 기록을 봅니다. 로그 위쪽의 자동 보고 켜짐·꺼짐과 바코드 원천 연결 상태를 봅니다.
2. **이력** 탭에서 그날 보고 실행의 단계 기록을 봅니다.
3. **대시보드** 할 일 카드의 상태와 `⋯` 메뉴의 갑지 건수를 봅니다.
4. 서버 문제로 보이면 운영자가 서비스 상태와 시스템 로그를 봅니다.
5. 정부 전송과 관련된 판단(재전송, 접수·미접수 정리)은 업무포털에서 사실을 확인한 뒤에만 합니다.
