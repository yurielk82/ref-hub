# 실제 경력과 업무 화면을 바탕으로 한 포트폴리오 재제작

## 확정된 목적과 범위

2026-11-01 오너는 수정된 클릭 시안을 본 뒤 실제 자료로 상세 계획을 세우고 진행하도록 지시했다. 기준은 독립 시안 소스 `7422d98`의 홈→사례 두 단계다. 최초 A·B·D 이미지의 개별 구성을 별도 페이지로 구현하지 않는다. 경력과 본인 기여를 먼저, 기능의 목적과 증거 화면을 같은 사례 안에 둔다.

대상: `/`, `/ax`, `/projects/*`, `/ax/cases/*`, 공통 탐색·푸터·화면 확대, 편집 필드 연결. 매뉴얼·로그인·제출 파일 생성과 공유 토큰은 보존한다. 공개하지 않은 거래처·직원·금액을 새로 가져오지 않는다. 실데이터란 검증된 경력 사실과 기존 공개용 비식별 캡처이며 운영 DB를 복사한다는 뜻이 아니다.

## 구현 단계

1. 편집 가능한 사례 투영: 기존 project 이름·요약, AX case 요약 키를 보존. 역할·문제·행동·결과·단계·화면 캡션에 안정된 상세 키를 추가한다. 경로·스크린샷 src·공유 토큰·운영 상태는 편집 문자열로 받지 않는다.
2. 홈: 남색·백색·청색의 선택 시안 구성. 왼쪽 소개, 오른쪽 실제 경력, 네 역량, 대표 사례 세 건의 넓은 행, 나머지 사례의 간결한 목록. 기존 순서 변경·초기화와 연락·경력·업무·AX 기술 자료를 유지한다.
3. 상세: 이름·기간·역할·현재 상태→문제/행동/결과→업무에 적용한 방식. 각 단계와 실제 화면을 바로 연결하며 같은 캡처는 한 번만 표시한다. 모든 핵심 근거는 확대 없이 본문에서 찾을 수 있다. 확대는 새 페이지나 새 탭을 만들지 않는다.
4. 탐색·표면: 기존 트랙 경계와 URL, 메타데이터 계약을 유지한다. 밝은/어두운 테마와 390px에서의 읽기 순서를 함께 설계한다. 기존 카드·그라데이션·이모지 중심 외형을 교체한다.
5. 검수·병합·배포: 서식·관련 정적 검사, 중앙 CI 또는 허용 서버 대기열, 두 축 코드 리뷰 후 PR 병합. 제품 개발 서버는 띄우지 않는다. 중앙 배포 뒤 이미 실행 중인 서버에서 desktop/mobile와 확대·복귀·기존 메뉴를 검사한다. 필수 finish reviewer와 documenter로 실제 화면 기준 DESIGN.md를 완성한다.

## 반례와 완료 기준

- 긴 실제 제목·캡션에서도 줄임표로 핵심을 숨기지 않고 모바일에 가로 넘침이 없다.
- 화면이 없는 단계·사례도 문제·행동·결과를 읽을 수 있다. 캡처를 만들었다고 성과를 추정하지 않는다.
- 본문의 각 실제 캡처는 한 번만 노출되고, 확대 종료 후 URL·스크롤·포커스가 보존된다.
- 기존 편집 키는 삭제하거나 다른 의미로 재사용하지 않는다. 새 상세 편집은 같은 저장·권한·충돌 방지 계약을 따른다.
- 두 트랙은 서로 링크하지 않는다. 기존 프로젝트·매뉴얼·공유 파일 URL이 유지된다.
- Nextra metadata에서 요청별 API를 호출하지 않는다. 운영 산출물을 확인용 빌드로 덮지 않는다.
- 실제 로그인 저장 검증을 수행하지 못하면 코드 검사와 구분해 보고한다.
